# ЛР-10. Структури папок

Ці таблиці заповнюєте ви: рядок «Де живе кошик» після кожної структури
(§4.3–§4.6) і «Вибір структури» наприкінці (§4.7). Рядок «Пакет» — лише якщо
виконуєте додаткове завдання §4.9. Як рахувати теки, описано в інструкції,
§4.2.

## Де живе кошик

У яких теках лежать шість файлів кошика: сховище, `useCart`,
`AddToCartButton`, `CartLine`, сторінка кошика й шапка з лічильником.
«Тек» — скільки їх, «Теки» — їхні шляхи через кому.

| Структура                  | Тек | Теки                                                                                    |
| -------------------------- | --- | --------------------------------------------------------------------------------------- |
| За типом файлів (§4.3)     | 4   | src/store, src/hooks, src/components, src/pages                                         |
| За маршрутами (§4.4)       | 2   | src/shared, src/routes/cart                                                             |
| За функціональністю (§4.5) |     |                                                                                         |
| FSD (§4.6)                 | 4   | src/features/cart/model, src/features/cart/ui, src/pages/cart/ui, src/widgets/header/ui |
| Пакет (§4.9)               |     |                                                                                         |

## Вибір структури

Описи проєктів, з чого обирати і як пояснити вибір — в інструкції, §4.7.
«Чому»: що в проєкті важливо і чому обрана структура для цього підходить.

| Проєкт                             | Структура             | Чому                                                                                                                                                                                                                                                             |
| ---------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Прототип на хакатоні            | За маршрутами         | П'ять екранів і короткий термін вимагають мінімуму правил: код кожного екрана лежить поруч, а команда з трьох людей швидко знаходить потрібні файли. Якщо прототип виросте, спільні частини можна винести в shared або перейти до структури за функціональністю. |
| 2. Блог і документація на Next.js  | За маршрутами         | У 40 сторінок переважає власна розмітка, а спільними є лише шапка й підвал. Colocation поруч із маршрутами спрощує редагування сторінки та відповідає організації Next.js.                                                                                       |
| 3. Адмінка для бариста             | За функціональністю   | Замовлення, склад і зміни мають власні таблиці, форми та бізнес-правила, але ділять базові кнопки й таблицю. Групування за функціональностями ізолює ці частини й полегшує роботу команди над окремими модулями.                                                 |
| 4. Інтернет-магазин кави           | Feature-Sliced Design | Проєкт розвивається роками, його підтримують три команди, а кошик і картка товару повторюються на багатьох сторінках. Шари, слайси та public API FSD задають напрямок залежностей і межі відповідальності для великого спільного коду.                           |
| 5. Три застосунки мережі кав'ярень | Пакети                | Сайт, кіоск і адмінка є окремими застосунками, яким потрібні спільні дизайн-система та кошик. Пакети дають чіткі публічні API, незалежні межі й можливість повторно використовувати код без імпортів між застосунками.                                           |
